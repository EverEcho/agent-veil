# ADR-0008：开发诊断日志与敏感请求正文边界

- 状态：已接受
- 范围：`internal/debugtrace`、Proxy 请求处理、Dashboard 设置

## 决策

安全审计继续禁止保存敏感原文。误脱敏排查使用独立的本机开发日志，并采用两级显式授权：

1. “开发模式”记录请求元数据、规则、Detector、最终 Action、字段路径、字节偏移、命中长度、置信度和已遮蔽上下文；
2. “记录原始请求正文”只有在开发模式开启时才可启用，并额外记录脱敏前正文和实际发送给上游的正文。

两项默认均关闭。正文记录不包含认证 Header 或 URL Query；单份正文限制为 256 KiB，日志保留 24 小时，总文件限制为 32 MiB，使用 `0600` 文件权限并淘汰最旧记录。管理 API 只允许本机已认证 Dashboard 访问，桌面桥仅放行精确端点。

## 原因

仅凭 Finding 类型和遮蔽摘要通常无法判断复杂历史上下文是否误报；但把请求原文加入常规审计会破坏产品默认不持久化敏感内容的信任边界。独立存储、二次开关、短保留期和有界容量使排障能力与默认隐私语义可以同时成立。

## 后果

- 关闭开发模式后不再产生新开发日志，但已有记录按保留期继续存在；
- 安全诊断导出不包含开发日志；
- UI 必须持续展示完整正文可能包含密钥、隐私数据和聊天历史的高风险提示；
- 新增响应正文、Header 或 Query 采集前必须重新评审本 ADR，不能复用当前授权自动扩张范围。
