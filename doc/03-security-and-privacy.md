# 安全与隐私设计

## 1. 保护目标

AgentVeil 主要防止以下数据通过受支持的 AI Agent 出口意外离开本机：

- API Key、Token、Cookie、密码、私钥和数据库连接串；
- 手机号、邮箱、身份证、银行卡等结构化 PII；
- Tool Call、Tool Result、日志、配置和上下文中的敏感内容；
- 模型响应中新出现或意外回显的凭据形态内容。

## 2. 威胁模型

### 范围内

- Agent 或插件无意携带敏感上下文；
- 多模型槽、Fallback 或子 Agent 绕过主模型保护；
- 未知/升级后的协议被误当作安全流量；
- 流式分片绕过占位符恢复或泄漏检测；
- 本地其他进程尝试调用代理路由；
- 日志、崩溃报告或审计二次泄漏；
- 代理链顺序错误导致 DLP 后内容再次被修改。

### 产品边界外的威胁

- 已取得当前用户权限并可读进程内存的本地恶意软件；
- Agent 通过未接管的任意子进程、DNS、原始 Socket 等恶意外传；
- 屏幕截图、键盘记录等系统级窃取；
- 用户显式关闭保护或选择放行后的数据泄漏；
- 检测 taxonomy 之外、无法可靠识别的语义敏感信息。

产品必须准确表述这些边界，不得把“已观察”描述为“已阻断”。

## 3. 安全不变量

1. 代理只监听 `127.0.0.1`/`::1` 的随机端口，不监听 `0.0.0.0`。
2. 每条本地路由必须携带不可预测的 Session/Route Token。
3. 未知协议、无法解析内容、不支持的压缩和检测器失败默认阻断。
4. Vault 只在内存中存在，容量有界；容量耗尽必须阻断。
5. 日志、指标、错误和审计不包含请求原文、Header 凭据、完整占位符映射。
6. Provider Upstream 必须来自已解析的 Protection Plan，客户端不得任意指定目标，防止开放代理和 SSRF。
7. 重写 Body 后再执行依赖 Body 的签名，例如 AWS SigV4。
8. 用户原始配置不得被永久覆盖；临时改动必须原子创建、位于带所有权标记的私有根目录、可恢复并在退出时清理。新 Core 只有取得独占实例锁后才能清理上一实例的残留，且不得认领或删除未标记目录中的未知数据。
9. 响应先做泄漏检测并执行同一 Policy，再恢复请求中的占位符；`redact` 必须保留正常协议终止事件，只有显式 `block` 才能中止。
10. 安全降级必须可见，不允许静默 passthrough。
11. CLI 从状态文件发现 Core 时，必须先以不携带管理凭据的请求校验随机实例身份；崩溃残留状态不得导致管理 Token 被发送到复用该回环端口的其他进程。
12. 浏览器管理界面不得接收管理 Token；只能由已认证的 CLI/桌面进程签发短期单次票据，经严格同源请求换取 `HttpOnly`、`SameSite=Strict`、作用域限于管理 API 的会话 Cookie。

## 4. 本地数据生命周期

| 数据 | 存储方式 | 生命周期 |
|---|---|---|
| Session Secret | 进程内存 | Session |
| Placeholder -> Original | 请求级内存 Vault | Request/Response |
| 桌面管理 Token | 用户私有配置文件；后续由 macOS/Windows 原生凭据库替换 | 桌面安装实例，卸载时清除 |
| 浏览器票据与会话 | Core 内存仅保存摘要；票据通过 URL fragment 短暂传递 | 票据 30 秒且单次使用；会话 8 小时或 Core 退出 |
| Agent 配置快照 | 最小化临时文件或内存 | Session，退出清理 |
| 审计事件 | 本地持久化 | 用户配置的保留期 |
| 敏感原文 | 禁止持久化 | 不适用 |

审计仅记录：时间、Agent、Surface、协议、Finding 类型、数量、严重级别、动作、延迟、错误码，以及全部命中值已替换为 `***` 的短上下文摘要。摘要必须限制长度、去除控制字符，并在持久化前再次执行泄漏扫描；工作区路径应默认哈希或相对化。

## 5. Upstream 与网络安全

- 只允许 Protection Plan 中的 scheme、host 和 port；
- 默认仅允许 HTTPS 远端 Upstream；本地 HTTP 需显式识别为 loopback；
- 禁止由请求 Header/Path 动态覆盖 Upstream；
- 设置连接、Header、Body、空闲与总请求超时；
- 限制重定向，重定向目标需再次通过 allowlist 校验；
- 限制请求/响应大小和解压后大小，防止压缩炸弹；
- TLS 校验默认开启，不提供静默跳过证书验证的降级路径。

## 6. 流式安全

流处理以协议事件而不是 TCP Chunk 为边界。实现必须维护有限 look-behind：

- 未闭合 `[[...]]` 占位符不得提前输出；
- Secret 或原始值可能跨 event 分割；
- Buffer 必须有上限，超限阻断而不是刷新可疑内容；
- Provider 断流时不得输出尚未判定安全的尾部；
- 每种协议建立分片、UTF-8 边界、错误 event 和提前 EOF 测试。

## 7. 测试要求

- Detector 单测包含真阳性、假阳性、边界与编码变体；
- 协议使用脱敏金样做 round-trip 测试；
- 使用随机分片属性测试验证 SSE 恢复；
- 使用模拟 Provider 证明远端只接收脱敏数据；
- 故障注入覆盖 detector panic、Vault full、代理中断、超时和无效压缩；
- 增加日志泄漏扫描，CI 中将测试 Secret 写入各路径并断言产物中不存在原文；
- 发布前进行本地代理 SSRF、开放代理、路径穿越和 Token 猜测测试。
